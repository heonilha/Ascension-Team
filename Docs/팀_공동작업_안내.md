## 처음 받기

저장소 소유자가 팀원의 GitHub 계정을 협업자로 초대하고, 팀원이 수락한 뒤 복제한다. 링크만으로 비공개 프로젝트 접근 권한이 생기지는 않는다.

```powershell
git clone https://github.com/kimminseoung-source/Ascension-Team.git
cd Ascension-Team
```

로컬 개발에 사용한 엔진은 Unreal Engine 5.8.3이며 C++ 빌드 도구가 필요하다. 프로젝트 파일은 `AscensionPrototype.uproject`, 기본 맵은 `Content/Maps/CombatLab.umap`이다. 실행에 사용하는 모델·맵·소스는 Git에 포함되어 있다. 제외된 Meshy 생성 원본과 API 키는 플레이에 필요하지 않다. 배포용 EXE는 아직 없다.

현재 PowerShell 스크립트의 기본 엔진/빌드 경로는 최초 개발 PC 기준이다. 다른 PC에서는 README의 명령을 그대로 실행하기 전에 경로를 확인해야 한다. `BuildDemo.ps1`은 `-EngineRoot`와 영문 경로의 `-BuildRoot`를 받을 수 있지만, `OpenDemo.ps1`과 검증 스크립트의 경로는 아직 공통화되지 않았다. 빌드 후 해당 빌드 폴더의 프로젝트 파일을 엔진에서 열 수 있다. 팀원 PC의 빌드와 실행은 별도 확인이 필요하다.

## 작업 순서

1. 에디터에서 저장한 뒤 종료하고, `main`의 최신 변경을 받는다. 커밋하지 않은 작업이 있으면 먼저 정리한다.
2. 담당 기능의 브랜치를 만든다. 예: `feature/boss-patterns`, `feature/ui`.
3. 기능별 한국어 제목으로 커밋하고 자신의 브랜치를 Push한다.
4. Pull Request로 변경 파일과 검증 결과를 공유하고, 검토 후 `main`에 합친다.
5. 팀원은 최신 `main`을 받은 뒤 소스 변경에 맞춰 다시 빌드한다.

같은 `.umap`/`.uasset` 파일을 동시에 수정하면 충돌을 합치기 어렵다. 맵·블루프린트·모델 담당 파일을 미리 나누고, 수정 전 서로 알린다. 강제 Push나 공유 브랜치 이력 재작성은 피한다.

## 파일 관리

`Binaries`, `Intermediate`, `Saved`, `DerivedDataCache`와 개인 IDE 설정/로그/인증 정보는 공유하지 않는다. 현재 `.gitignore`를 유지한다. 게임 데이터는 `Content`, 코드는 `Source`, 공통 설정은 `Config`에 둔다. 새 대형 에셋이나 Git LFS 도입은 팀에서 범위를 정한 뒤 진행한다.
