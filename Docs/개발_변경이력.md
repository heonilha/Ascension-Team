## 2026-11-03 P1 회피 판정 서버 이전과 모드별 지연 보정

- 결정: 회피 무적(0.15초)이 왕복 지연보다 짧은 문제를 "서버가 명중 시각을 정하고, 회피 입력에 누른 시각을 붙이고, 명중 판정을 허용 되감기만큼 유예"하는 방식으로 푼다. PvE와 PvP의 되감기 상한을 분리했다(PvE 200ms, PvP 100ms). PvP는 무적을 0.30초로 늘려 왕복 100ms가 무적의 1/3을 넘지 않게 했고, 공격 준비 0.35초를 둔다. 조작 이득은 상한까지로 묶인다.
- 프로토콜 v2: 방 모드(PvE 3명 / PvP 16명), 모드 규칙과 서버 시각을 담은 S_EnterRoom, C_Dodge·C_Attack(누른 시각), S_AttackStart(명중 시각), S_HitResult. 서버 원본과 이 저장소 사본은 같은 내용이다.
- 클라이언트: -AscensionMode=pvp 옵션(OpenOnline.ps1 -Mode), 회피·공격 시각 전송, 서버 예고 원 표시, 서버 판정 반영(정확한 회피 보상 또는 피해), 모드별 무적 시간 적용, HUD 표시, 시험 옵션 -AscensionNetAutoDodge.
- 실제 클라이언트 시험에서 찾아 고친 것: 서버 시계 추정을 게임 스레드 처리 시각이 아니라 수신 스레드 도착 시각으로 측정, 가장 좋았던 측정 하나 대신 최근 1초(0.2초 간격 Ping 5개) 중 왕복이 가장 짧은 측정을 사용.
- 환경 문제: 이 PC의 WSL 시계가 Windows보다 간헐적으로 수 %~10% 빠르게 흐른다(재시작 직후 0.06%, 이후 4.6%로 튐). 클라이언트 보강으로 판정은 맞게 나오지만 시계 오차 10~40ms가 남는다. 실제 서버를 둘 Linux 서버에서는 다시 측정해야 한다.
- 남은 한계: 몬스터·수문장·검기·스킬은 아직 서버 판정이 아니다. PvE의 서버 공격은 내려찍기 시험 패턴(--pve-slam-ms)뿐이다. 서버 HP는 판정 기록용이며 사망·부활 흐름이 없다. 서버 판정 피해에는 방어구 감소가 없다. 이동은 여전히 클라이언트 위치 전송 + 서버 검증이다.

## 2026-11-05 P1 서버 권한 이동(프로토콜 v3)

- 결정: 클라이언트 위치 전송 + 서버 검증을 입력 전송 + 서버 이동 계산으로 바꿨다. 서버·봇·클라이언트가 같은 이동 코드(AscensionMovement.h, C++20)를 컴파일해 쓰므로 정상 입력이면 예측과 서버 결과가 일치하고, 재조정은 지연이나 조작이 있을 때만 일어난다.
- 클라이언트: 온라인에서만 주인공 위치를 공유 이동 코드가 정한다(언리얼 이동 MOVE_None). 60Hz 예측, 30Hz 입력 전송, S_MoveAck 재조정, 차이는 0.1초 동안 녹임. 1인 데모 이동은 그대로다.
- 서버: 입력 처리권(초당 60개, 최대 0.5초 분량)으로 속도 조작을 막고, 본인에게 S_MoveAck를 20Hz로 보낸다. C_Move·S_Correction과 토큰 버킷 검증은 없앴다.
- 남은 일: 몬스터 서버 이전(같은 지형·이동 코드 재사용), 수문장 패턴, 검기 서버 스윕, 성장 검증.

- 동작 섞기(`HeroMotion`): 주인공은 1인 데모·온라인 모두 섞는 동작으로 그린다(전에는 생존 모드에서만 섞고, 나머지는 클립을 바로 갈아 끼워 끊겼다).
  - 이동: 속도로 대기 → 걷기 → 달리기 비중을 정하고, 걸음 주기를 실제 이동 거리로 돌려 재생 속도가 이동 속도를 따른다(최고 450cm/s면 달리기 1.15배속).
  - 공격: 클립의 칼이 가장 빠른 순간이 게임 판정 시각(약 0.28초·강 0.46초)에 오도록 앞뒤 구간을 따로 맞춘다. 모으는 동안은 칼을 든 자세까지 천천히 간다.
  - 회피: 골반 이동을 지워 제자리로 만들고, 평균 몸 정면을 회피 방향으로 돌린다. 재생 위치는 게임이 실제 옮긴 거리 비율로 정해 클립 속 구르는 거리와 실제 이동이 같다(미끄러짐 없음).
  - 동작이 바뀌거나 같은 공격을 다시 시작할 때 0.12초 섞는다. 다른 플레이어(온라인)도 같은 시간표·거리 곡선을 쓴다.
- 이동 방향 회전: 몸이 카메라 방향 대신 이동하는 방향으로 돈다(초당 보간 12). 락온 중에는 대상을, 공격·회피 시작 때는 조준·회피 방향을 본다. 멈추면 마지막 방향을 유지한다. 온라인으로 보내는 방향도 이 값이라 다른 사람 화면에서도 같다. 회귀 시험의 "이동 중 카메라 방향" 확인을 "움직인 쪽으로 돈다"로 바꿨다.
- 한계: 검은 아직 상자 모양이고 믹사모 베기의 칼 각도와 맞추지 않았다. 강공격은 약공격과 같은 클립(구간만 다름)이다. 걷기·달리기는 같은 위상이라고 보고 섞었고, 방향 전환 중 발 미끄러짐은 따로 맞추지 않았다.
