# 데모 작업 분담

작성일: 2026-11-27. 기준 기획은 [11.26 기획안](11.26기획안.md)이다. 기획이 바뀌면 기획안을 먼저 고치고 이 문서의 범위를 맞춘다.

## 데모 목표 (초안, 팀 합의 필요)

기획안 전체가 아니라 **핵심 한 판의 흐름**을 짧게 보여 주는 간단한 데모다.

PvP 맵에서 바로 시작 → 몬스터 사냥으로 레벨업 → 검·활을 바꿔 가며 스킬 사용 → 자기장 축소 → 다른 팀과 전투 → 최후의 1팀 승리.

| 포함 | 데모에서 뺌 (이후 단계) |
| --- | --- |
| 맵 1개, 팀 단위 접속 (시험은 2팀 × 1~3명부터) | 4팀 × 3명 12명 정원 부하 확인 |
| 몬스터 사냥 경험치, 레벨업 | 레벨별 경험치 표 최종 수치 |
| 검·활 동시 지급과 교체, 스킬 사용 시 자동 교체 | 스킬 지우기·포인트 환급 |
| 검 스킬, 활 스킬 (담당자별 범위는 아래) | 고급 스킬 각성 |
| 라운드 시간과 자기장 축소·자기장 밖 피해 (짧게 줄인 시간) | 균열, 황금 고블린, 특성, 장비 |
| 부활 대기와 마지막 라운드 탈락, 최후의 1팀 판정 | 스탯 분배 UI (데모는 고정 스탯 가능) |
| HUD: 체력·마나·레벨·스킬 쿨타임·라운드/자기장 시간·남은 팀 | 상점·로비·매치메이킹 |

| 담당 | 범위 | 주 작업 위치 |

## 스킬 담당과 맞출 약속

검·활 담당이 서버를 몰라도 작업할 수 있게, 그리고 PvP 공정성을 위해 판정은 결국 서버가 하도록 아래 순서로 나눈다.

1. **스킬 담당은 먼저 오프라인(1인 플레이)으로 구현한다.** 입력 → 동작 → 범위 → 피해 → 이펙트가 혼자 플레이에서 보이면 된다.
2. **스킬 수치는 한 곳에 모은다.** 범위 모양(원·부채꼴·직선·투사체)과 크기, 배율, 쿨타임, 마나, 준비 시간, 특수 효과(경직·슬로우·넉백·무적·버프 시간)를 스킬별 데이터로 두고 코드 곳곳에 숫자를 흩지 않는다. 서버 담당이 이 데이터를 서버로 옮긴다.
3. **판정 함수를 분리한다.** "누가 맞았는가"를 계산하는 부분과 "보여 주는" 부분(애니메이션·이펙트·소리)을 다른 함수로 둔다. 온라인에서는 판정 부분만 서버로 옮기고 보여 주는 부분은 그대로 쓴다.
4. 서버 담당이 스킬별 패킷과 서버 판정을 붙인다. 스킬 담당은 온라인에서 동작이 맞는지 확인한다.

현재 클라이언트 코드는 `CombatLab.cpp` 한 파일(약 1,900줄)에 거의 모든 전투가 들어 있어, 세 명이 동시에 고치면 충돌이 잦다. 스킬 작업 시작 전에 스킬 공통 틀(무기 교체·스킬 슬롯·쿨타임·마나)과 검/활 전용 파일을 나누는 작업을 먼저 한다. 이 틀을 누가 언제 만들지는 팀에서 정한다.

## 브랜치·커밋·푸시

모여서 작업하지 않고 각자 시간 날 때 작업하므로, 다른 사람이 언제든 최신 상태를 볼 수 있게 자주 올린다.

- 담당별 브랜치에서 작업한다. 예: `feature/server-br-room`, `feature/map-zone`, `feature/ui-hud`, `feature/sword-skills`, `feature/bow-skills`.
- **작업을 마칠 때마다 커밋하고 푸시한다.** 끝나지 않은 작업도 빌드가 되면 브랜치에 푸시해 둔다. 빌드가 깨진 상태는 main에 합치지 않는다.
- 커밋은 기능 하나 단위로 작게 나누고 한국어 제목을 쓴다. 예: `기능: 검 강타 스킬 추가`, `수정: 활 속사 쿨타임 적용`.
- 작업 시작 전에 main의 최신 변경을 자기 브랜치에 받는다. 오래 벌어질수록 합치기 어렵다.
- 스킬 하나가 완성되면 Pull Request로 main에 합친다. 큰 묶음을 한 번에 올리지 않는다.
- 공용 파일(`CombatLab.cpp/h`, `CLNetSession.*`, `AscensionProtocol.h`, `Content/Maps/*.umap`, `Config/*.ini`)을 고칠 때는 미리 팀에 알린다. `.umap`·`.uasset`은 한 번에 한 사람만 고친다.
- 에디터가 자동으로 바꾼 `Config` 변경이나 개인 설정(예: Android File Server 토큰)은 커밋하지 않는다.
- 강제 푸시와 공유 브랜치 이력 재작성은 하지 않는다.
