# 데모 작업 분담

작성일: 2026-11-27. 기준 기획은 [11.26 기획안](11.26기획안.md)이다. 기획이 바뀌면 기획안을 먼저 고치고 이 문서의 범위를 맞춘다.

## 데모 목표 (초안, 팀 합의 필요)

기획안 전체가 아니라 **핵심 한 판의 흐름**을 짧게 보여 주는 간단한 데모다.

PvP 맵에서 바로 시작 → 몬스터 사냥으로 레벨업 → 검·활을 바꿔 가며 스킬 사용 → 자기장 축소 → 다른 팀과 전투 → 최후의 1팀 승리.

| 포함 | 데모에서 뺌 (이후 단계) |
| --- | --- |
| 맵 1개, 팀 단위 접속 (시험은 2팀 × 1~3명부터) | 4팀 × 3명 12명 정원 부하 확인 |
| 몬스터 사냥 경험치, 레벨업 | 레벨별 경험치 표 최종 수치 |
| 검·활 동시 지급과 교체, 스킬 사용 시 자동 교체 | 스킬 지우기·포인트 환급 |
| 검 스킬, 활 스킬 (담당자별 범위는 아래) | 고급 스킬 각성 |
| 라운드 시간과 자기장 축소·자기장 밖 피해 (짧게 줄인 시간) | 균열, 황금 고블린, 특성, 장비 |
| 부활 대기와 마지막 라운드 탈락, 최후의 1팀 판정 | 스탯 분배 UI (데모는 고정 스탯 가능) |
| HUD: 체력·마나·레벨·스킬 쿨타임·라운드/자기장 시간·남은 팀 | 상점·로비·매치메이킹 |

## 역할

| 담당 | 범위 | 주 작업 위치 |
| --- | --- | --- |
| 맵·서버·UI (heonilha) | 맵 수정, 서버 방 규칙(팀·라운드·자기장·부활·승리), 서버 몬스터, 스킬 서버 판정 연결, HUD | Ascension-Server 전체, `Content/Maps`, 클라이언트 네트워크·HUD 코드 |
| 검 스킬 | 기획안 "검 스킬" 표의 스킬 구현 (동작·범위·피해·쿨타임·마나·특수 효과·이펙트) | 검 스킬 전용 소스 파일 |
| 활 스킬 | 기획안 "활 스킬" 표의 스킬 구현. 수치가 비어 있으면 검 스킬 티어 기준으로 초안을 정해 기획안에 적는다 | 활 스킬 전용 소스 파일 |

데모에 넣을 스킬 개수는 각 담당자가 정한다. 권장은 초급·중급을 먼저 끝내고 고급은 시간이 남으면 추가하는 순서다.

## 스킬 담당과 맞출 약속

검·활 담당이 서버를 몰라도 작업할 수 있게, 그리고 PvP 공정성을 위해 판정은 결국 서버가 하도록 아래 순서로 나눈다.

1. **스킬 담당은 먼저 오프라인(1인 플레이)으로 구현한다.** 입력 → 동작 → 범위 → 피해 → 이펙트가 혼자 플레이에서 보이면 된다.
2. **스킬 수치는 한 곳에 모은다.** 범위 모양(원·부채꼴·직선·투사체)과 크기, 배율, 쿨타임, 마나, 준비 시간, 특수 효과(경직·슬로우·넉백·무적·버프 시간)를 스킬별 데이터로 두고 코드 곳곳에 숫자를 흩지 않는다. 서버 담당이 이 데이터를 서버로 옮긴다.
3. **판정 함수를 분리한다.** "누가 맞았는가"를 계산하는 부분과 "보여 주는" 부분(애니메이션·이펙트·소리)을 다른 함수로 둔다. 온라인에서는 판정 부분만 서버로 옮기고 보여 주는 부분은 그대로 쓴다.
4. 서버 담당이 스킬별 패킷과 서버 판정을 붙인다. 스킬 담당은 온라인에서 동작이 맞는지 확인한다.

## 스킬 공통 틀 (2026-11-27 추가)

전투 코드가 `CombatLab.cpp` 한 파일에 몰려 있어, 스킬은 별도 파일로 나눴다. **검·활 담당은 자기 파일만 고친다.**

| 파일 | 담당 | 내용 |
| --- | --- | --- |
| `Source/AscensionPrototype/CLSwordSkills.cpp` | 검 스킬 | 검 스킬 12개 표와 구현. 예시로 **강타** 구현 |
| `Source/AscensionPrototype/CLBowSkills.cpp` | 활 스킬 | 활 스킬 12개 표와 구현. 예시로 **속사** 구현(임시 수치) |
| `CLSkillTypes.h` | 공용 (바꾸기 전 알림) | 스킬 데이터 구조 `FCLSkillDef`: 스탯·티어·판정 모양·거리·반경·배율·타수·쿨타임·마나·준비/동작 시간 |
| `CLSkillLibrary.h/.cpp` | 공용 (추가는 자유, 수정은 알림) | 판정(원·부채꼴·직선 안의 몬스터), 효과(피해·경직·투사체·돌진), 표시(개발용 선) 도우미 |
| `CLSkillComponent.h/.cpp` | 맵·서버·UI | 무기 교체, 슬롯 4개, 쿨타임, 마나, 버프 시간, 피해 공식 |
| `CLSkillVerify.*`, `Scripts/VerifySkills.ps1` | 공용 | 틀 자동 시험 |

스킬 하나 만드는 순서:

1. 자기 파일의 표에서 해당 줄의 수치를 확인하고, 마지막 칸(실행 함수) `nullptr`을 새 함수 이름으로 바꾼다.
2. 함수는 **판정 → 효과 → 표시** 순서로 쓴다. 예시 `Smash()`(강타)와 `Rapid()`(속사)를 참고한다.
3. 수치는 표에만 둔다. 함수는 `Ctx.Def->Range`, `Ctx.Damage`처럼 표 값을 읽는다.
4. 시험: 에디터나 게임을 `-AscensionSkills=Sword.Smash,Sword.Spin,Bow.Rapid,None`처럼 실행해 원하는 스킬을 슬롯에 넣는다. 옵션이 없으면 구현된 검 스킬 2개 → Z·X, 활 스킬 2개 → C·V에 자동으로 들어간다.
5. 빌드 후 `.\Scripts\VerifySkills.ps1 -BuildRoot <빌드 경로>`가 통과하는지 확인하고 커밋·푸시한다.

틀이 정한 규칙:

- 피해 = 공격력 × 배율 × (1 + 해당 스탯 × 0.01). 공격력 = 20 + 힘 × 2 (데모 임시).
- 스탯은 데모에서 모두 5 고정(분배 UI 없음). 마나 = 100 + 지능 × 5, 초당 4 × (1 + 지능 × 1%) 회복 (임시).
- 스킬을 쓰면 해당 무기로 자동 교체. 준비 시간(`CastTime`)이 있으면 시전 순간의 조준 방향으로 시간이 지난 뒤 실행하고, 그 전에 회피하면 취소된다. 동작 시간(`ActionTime`) 동안 일반 공격·다른 스킬을 막는다.
- 임시 조작: **Z / X / C / V** 스킬 슬롯, **F** 무기 교체. 이전 기획 조작(1/2/3 각성, Q, E, R)과 겹치지 않게 골랐고, 이전 기능을 정리할 때 다시 정한다.
- 스킬 바는 화면 오른쪽 아래에 무기·마나·슬롯 4칸·쿨타임을 표시한다. 회색 칸은 아직 구현되지 않은 스킬이다.

현재 한계:

- 1인(오프라인) 플레이의 몬스터만 맞는다. 온라인에서는 몬스터가 서버가 움직이는 꼭두각시라 스킬 피해가 무시되고, 플레이어 대상 피해도 없다. 서버 판정은 맵·서버 담당이 붙인다.
- 활 모델·동작이 없어 활로 바꾸면 검만 숨긴다. 스킬 동작은 검 휘두르기 동작을 재사용하고, 화살은 검기 투사체를 임시로 쓴다.
- 일반 공격(좌클릭·우클릭)은 아직 무기와 상관없이 기존 검기다.
- 슈퍼아머·무적·도발·슬로우·보호막 흡수처럼 몬스터나 피격 처리에 손대야 하는 효과는 아직 도우미가 없다. 필요하면 `CLSkillLibrary`에 추가하고 팀에 알린다.

## 브랜치·커밋·푸시

모여서 작업하지 않고 각자 시간 날 때 작업하므로, 다른 사람이 언제든 최신 상태를 볼 수 있게 자주 올린다.

- 담당별 브랜치에서 작업한다. 예: `feature/server-br-room`, `feature/map-zone`, `feature/ui-hud`, `feature/sword-skills`, `feature/bow-skills`.
- **작업을 마칠 때마다 커밋하고 푸시한다.** 끝나지 않은 작업도 빌드가 되면 브랜치에 푸시해 둔다. 빌드가 깨진 상태는 main에 합치지 않는다.
- 커밋은 기능 하나 단위로 작게 나누고 한국어 제목을 쓴다. 예: `기능: 검 강타 스킬 추가`, `수정: 활 속사 쿨타임 적용`.
- 작업 시작 전에 main의 최신 변경을 자기 브랜치에 받는다. 오래 벌어질수록 합치기 어렵다.
- 스킬 하나가 완성되면 Pull Request로 main에 합친다. 큰 묶음을 한 번에 올리지 않는다.
- 공용 파일(`CombatLab.cpp/h`, `CLNetSession.*`, `AscensionProtocol.h`, `Content/Maps/*.umap`, `Config/*.ini`)을 고칠 때는 미리 팀에 알린다. `.umap`·`.uasset`은 한 번에 한 사람만 고친다.
- 에디터가 자동으로 바꾼 `Config` 변경이나 개인 설정(예: Android File Server 토큰)은 커밋하지 않는다.
- 강제 푸시와 공유 브랜치 이력 재작성은 하지 않는다.
