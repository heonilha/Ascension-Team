# 온라인 P0 실행 안내

작성일: 2026-10-28. 서버 담당(Heonilha).

P0 목표는 **같은 팀 코드로 접속한 플레이어끼리 같은 층에서 서로 움직이는 모습을 보는 것**이다. 전투 판정·몬스터 동기화는 아직 없다.

## 구성

| 위치 | 내용 |
|---|---|
| 서버 저장소 `Ascension-Server` (별도) | GCC·C++26·asio 서버, 봇 클라이언트, **프로토콜 원본** `protocol/AscensionProtocol.h` |
| 이 저장소 `Source/AscensionPrototype/AscensionProtocol.h` | 프로토콜 **복사본**. 직접 고치지 않는다 |
| `CLNetSession.h/.cpp` | 서버 접속 액터. 수신 스레드 + 게임 스레드 패킷 처리, 15Hz 이동 전송 |
| `CLRemoteHero.h/.cpp` | 다른 플레이어의 겉모습. 서버 위치를 0.1초 늦게 보간해서 그린다 |
| `CombatLab.h/.cpp` | `-AscensionServer` 옵션이 있을 때만 온라인 모드. 몬스터 생성을 끄고 HUD에 접속 상태 표시 |
| `Scripts/OpenOnline.ps1` | 온라인 옵션으로 게임 실행 |

옵션 없이 실행하면 기존 1인용 데모와 똑같이 동작한다. 자동 검증 옵션(`-AscensionVerify` 등)과 함께 쓰면 온라인 모드가 켜지지 않는다.

## 실행 순서 (한 PC에서 두 클라이언트)

1. **서버 켜기**: WSL 터미널에서 서버 저장소를 빌드하고 실행한다. 자세한 방법은 서버 저장소 README 참고.
   ```bash
   ./build/debug/ascension_server --port 7777
   ```
2. **클라이언트 빌드**: PowerShell에서 이 저장소 폴더로 이동한 뒤, 영문 경로의 빌드 폴더를 지정한다.
   ```powershell
   .\Scripts\BuildDemo.ps1 -BuildRoot C:\Builds\AscensionPrototype
   ```
3. **클라이언트 두 개 실행**: 이름만 바꿔 두 번 실행한다. 팀 코드가 같아야 같은 층에 들어간다.
   ```powershell
   .\Scripts\OpenOnline.ps1 -BuildRoot C:\Builds\AscensionPrototype -Name player1 -Team 1
   .\Scripts\OpenOnline.ps1 -BuildRoot C:\Builds\AscensionPrototype -Name player2 -Team 1
   ```
4. **확인**: 체력바 위 하늘색 줄에 `온라인 · 팀 1 · 같은 층 2/3명 · 지연 Nms`가 보이고, 상대 캐릭터 머리 위에 이름이 보이면 성공이다.

다른 PC의 서버에 붙을 때는 `-Server 192.168.0.10:7777`처럼 서버 PC의 IPv4 주소를 넣는다.

## 규칙

- 한 팀(층 인스턴스)은 최대 3명이다. 4번째는 "팀 방이 가득 찼습니다"가 표시된다.
- 프로토콜을 바꿀 때는 서버 저장소의 원본을 고치고 `kVersion`을 올린 뒤, 이 저장소의 복사본도 같은 PR 시점에 갱신한다. 버전이 다르면 서버가 로그인을 거부하고 HUD에 버전 불일치가 표시된다.

## P1: 서버 회피 판정 (2026-11-03 추가, 프로토콜 v2)

회피 무적과 공격 명중을 서버가 판정한다. 방은 모드별로 나뉜다.

| 모드 | 실행 옵션 | 정원 | 회피 무적 | 회피 입력 되감기 상한 |
|---|---|---|---|---|
| PvE (기본) | `-Mode pve` | 3명 | 0.15초 | 200ms |
| PvP 스테이지 | `-Mode pvp` | 16명 | 0.30초 | 100ms |

```powershell
.\Scripts\OpenOnline.ps1 -BuildRoot C:\Builds\AscensionPrototype -Name player1 -Team 5 -Mode pvp
.\Scripts\OpenOnline.ps1 -BuildRoot C:\Builds\AscensionPrototype -Name player2 -Team 5 -Mode pvp
```

- PvP 방에서는 일반·강공격이 서버 공격(`C_Attack`)으로 나간다. 서버가 0.35초 뒤 명중을 정해 모두에게 알리고, 바닥에 빨간 원으로 예고가 보인다.
- PvE 방의 공격 대상(몬스터)은 아직 서버에 없다. 회피 판정을 보려면 서버를 `--pve-slam-ms 1500`으로 켠다. 1.5초마다 플레이어를 번갈아 노리는 주황색 내려찍기 시험 패턴이 나온다.
- 회피하면 누른 시각을 서버에 보낸다. 서버는 명중 시각이 그 회피의 무적 구간 안이면 "정확한 회피", 아니면 피격으로 판정한다. 판정은 명중 후 지연만큼(최대 상한) 기다렸다가 확정하므로 피격 표시가 0.1초 안팎 늦을 수 있다.
- HUD 하늘색 줄에 모드·정원·무적 시간·서버 판정 회피/피격 수가 보인다.
- 시험 옵션 `-AscensionNetAutoDodge`: 나를 노린 공격을 하나 걸러 하나씩 자동으로 회피한다(화면 없는 검증용).
- 원리와 수치를 정한 이유는 서버 저장소 README의 "회피 판정과 지연 보정 (P1)"에 있다.

## P1: 서버 충돌 지형 (2026-11-03 추가)

서버가 맵의 기둥·벽·바위를 알고 이동과 공격을 지형으로도 검사한다. 기둥을 뚫는 이동은 되돌려지고(`S_Correction`), 기둥 너머의 상대는 공격에 맞지 않는다.

- 서버용 지형 파일은 실제 맵에서 뽑는다. **맵(CreateMap.py)을 바꾸면 다시 내보내고 서버 저장소 `data/`에 복사한다.**
  ```powershell
  & "C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" "$PWD\AscensionPrototype.uproject" -run=pythonscript "-script=$PWD\Scripts\ExportServerCollision.py" -unattended -nullrhi -nosplash
  # 결과: Data\ServerCollision\CombatLab.txt → 서버 저장소 data\CombatLab.txt
  ```
- 내보낸 파일이 실제 충돌과 같은지 게임을 띄워 확인한다(40cm 격자, 주인공 캡슐 겹침 비교). 로그에 `ASCENSION_COLLISION_VERIFY PASS`가 나와야 한다.
  ```powershell
  & "C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" "$PWD\AscensionPrototype.uproject" -game -nullrhi -unattended -nosplash -AscensionCollisionVerify -abslog="$PWD\Saved\Logs\CollisionVerify.log"
  ```
- 늘린 구(엄폐 바위 2.2×2.7×1.9)는 물리가 늘리지 못해 가장 작은 축(반지름 95cm) 구로 충돌한다. 내보내기도 이 기준을 따른다. 바위 겉모습보다 실제로 더 가까이 붙을 수 있는 것은 기존 1인 데모와 같다.
- 에디터 커맨드렛 실행 뒤 `Config/DefaultEngine.ini`에 Android 파일 서버 설정이 자동으로 붙을 수 있다. 이번 작업과 무관하므로 커밋하지 않는다.

## P0의 한계 (다음 단계에서 바꿀 것)

- **이동은 클라이언트가 위치를 보내고 서버가 검증하는 방식이다.** 서버는 속도(토큰 버킷)와 맵 범위를 확인하고 벗어나면 되돌린다(`S_Correction`). 합의한 "판정은 서버" 원칙에 맞추려면 서버에 충돌 지형이 필요하다. 지형이 준비되면 입력 전송 + 서버 이동 계산으로 바꾼다.
- 몬스터·수문장·경험치·장비 드롭은 온라인 모드에서 꺼져 있다.
- 공격·강공격·회피는 상대 화면에 **애니메이션만** 보인다. (P1에서 PvP 근접 공격과 회피 무적은 서버가 판정한다. 검기·스킬·각성 효과는 아직 서버 판정이 없다.)
- R(새 도전)의 시작 위치 순간이동은 서버가 거부해 원래 자리로 돌아올 수 있다.
- 서버 주소는 IPv4만 지원한다(`localhost`는 127.0.0.1로 바꿔 처리).
- 이름은 UTF-8 31바이트까지(한글 약 10자)만 전송된다.
- 이 변경은 Linux에서 서버·봇 테스트만 했다. **언리얼 빌드와 실제 두 클라이언트 접속은 Windows PC에서 확인이 필요하다.**
