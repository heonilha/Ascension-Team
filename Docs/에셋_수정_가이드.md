# Ascension-Team 언리얼 에셋 수정 가이드

대상: `AscensionPrototype.uproject` · Unreal Engine 5.8.3 · 테스트 맵 `Content/Maps/CombatLab.umap`

**담당 파일 조율 → 작업 브랜치 → 언리얼에서 수정·저장 → Play 확인 → Commit·Push → PR** 순서로 진행한다.

## 1. 작업 준비

같은 `.uasset`이나 `.umap`은 한 번에 한 사람이 수정한다. 바이너리 파일은 텍스트처럼 변경 부분을 합치기 어렵다. 특히 공용 전투 맵 `CombatLab`을 바꿀 때는 팀에 먼저 알린다.

저장소는 `C:\Projects\Ascension-Team`처럼 영문 경로에 클론한다. 작업 트리가 깨끗한지 확인한 뒤 아래 명령을 실행한다.

```powershell
git status --short
git switch main
git pull --ff-only
git switch -c feature/asset-material
```

변경 중인 파일이 있으면 먼저 정리한다. `pull --ff-only`가 실패하면 강제로 덮어쓰지 말고 팀에 알린다. 에디터를 열 때는 [빌드와 실행](../README.md#빌드와-실행)을 참고한다. 팀원 PC에서 실행 스크립트를 쓰려면 엔진·빌드 경로를 각자 환경에 맞춰야 한다. 별도 빌드 사본에서 에셋을 수정했다면, 검증한 파일을 원본 저장소의 같은 경로에 반영한 뒤 Git 변경을 확인한다.

## 2. 언리얼에서 수정

| 작업 | 에디터에서 하는 방법 |
| --- | --- |
| 새 모델·텍스처 추가 | **Content Drawer → Import**로 프로젝트 `Content/`에 가져온다. |
| 기존 모델·텍스처 갱신 | 원본을 수정해 다시 내보낸 뒤 기존 에셋 우클릭 → **Reimport**. 원본 경로가 바뀌면 해당 에셋의 파일 교체 옵션을 사용한다. |
| 재질·블루프린트 수정 | 에셋을 더블클릭해 편집한다. 한 오브젝트의 색만 바꿀 때는 전용 Material Instance를 사용한다. 블루프린트는 **Compile → Save**를 실행한다. |
| 맵에 배치 | 에셋을 레벨로 드래그하고 위치·회전·크기·충돌을 확인한 뒤 맵을 저장한다. |

다른 Unreal 프로젝트에서 옮길 때는 **Asset Actions → Migrate**로 필요한 참조 에셋을 함께 가져온다. 이름 변경·이동·삭제는 에디터에서 한다. **Reference Viewer**로 어디서 사용하는지 확인하고, 이동 후에는 해당 폴더의 리다이렉터와 C++·설정에 직접 적힌 경로도 확인한다.

## 3. Play 확인 후 PR 올리기

1. **Save All** 후 `CombatLab`을 열어 **Play**로 외형·크기·재질·충돌을 확인한다. 캐릭터 변경이면 스켈레톤과 애니메이션도 확인한다.
2. `git status --short`로 수정 파일을 보고, 변경 의도가 있는 에셋·맵·참조 파일만 스테이징한다. 아래 에셋 경로와 브랜치명은 예시다.

```powershell
git add -- Content/Props/MI_TestCrate.uasset
git diff --cached --name-status
git diff --cached --check
git commit -m "에셋: 테스트 상자 재질 추가"
git push -u origin feature/asset-material
```

3. `main`을 대상으로 PR을 열고 **수정한 에셋 / 확인한 맵 / 실제 Play 결과**를 적는다.

**Ascension-Team은 현재 `.uasset`과 `.umap`을 일반 Git 바이너리로 관리한다.** 기존 졸업작품 저장소의 Git LFS 절차는 이 저장소에 적용하지 않는다. 대형 원본 업로드나 LFS 전환은 먼저 팀과 범위를 정한다. Meshy 원본, 인증 정보, `Saved/`·`Intermediate/`·`Binaries/` 등은 커밋하지 않는다. 바이너리 충돌이 나면 각 작업자의 변경을 보존한 채 어느 버전을 기준으로 에디터에서 다시 적용할지 정한다.
